# Product Guidelines

## Communication & Prose Style
*   **Technical and Precise:** Documentation and developer communications must prioritize technical accuracy, especially concerning memory safety and Zig implementation details. 
*   **Clarity through Precision:** Avoid ambiguity by using standard systems programming terminology and providing detailed explanations for low-level behaviors.

## Design Principles
*   **Explicit over Implicit:** The language should avoid "magic" or hidden behaviors. Code should be easy to read and reason about, with explicit declarations and clear control flow.
*   **Composition over Inheritance:** Encourage building complex systems through the composition of simple, reusable components rather than deep inheritance trees.
*   **Fail Fast:** The system should identify and report errors as early as possible—preferably at compile-time or through strict runtime checks—to prevent silent failures.

## Visual Identity & Brand Messaging
*   **Professional and Robust:** Maintain a clean, minimalist aesthetic that projects stability, reliability, and readiness for serious development.
*   **Innovation-Focused:** Messaging should highlight the unique synergy between Zig and Mufi-Lang, positioning MufiZ as a cutting-edge tool for modern systems programming and scripting.
