# MufiZ C Header Generation

## Overview

The `include/mufiz.h` header file is **automatically generated** from the C API implementation in `src/c_api.zig`. This ensures that the header always stays in sync with the actual exported functions.

## Source of Truth

- **Implementation**: `src/c_api.zig` - The actual C API implementation with all exported functions
- **Generator**: `scripts/gen_header.zig` - Generates the comprehensive C header
- **Output**: `zig-out/include/mufiz.h` - The generated header file

## How It Works

1. The header generator (`scripts/gen_header.zig`) reads `build.zig.zon` to extract the version
2. It generates a comprehensive C header with:
   - Platform-specific export/import macros
   - All constant definitions
   - Complete function declarations with documentation
   - Usage examples
3. The header is written to `zig-out/include/mufiz.h`

## Generating the Header

### Manual Generation

To generate the header manually:

```bash
zig build header
```

This will create/update `zig-out/include/mufiz.h`.

### Validating the Header

To validate that the generated header matches all exports in `src/c_api.zig`:

```bash
zig build validate-header
```

This will:
1. Generate the header (if not already generated)
2. Extract all `export fn` declarations from `src/c_api.zig`
3. Extract all function declarations from the generated header
4. Verify that every exported function has a corresponding header declaration
5. Exit with code 0 on success, 1 on failure

### Automatic Generation

The header is automatically generated and validated when:

1. Building the shared library: `zig build`
2. Running the release script: `scripts/prepare_release_artifacts.sh`
3. Running validation: `zig build validate-header`

## Build Integration

The header generation is integrated into `build.zig`:

```zig
// Generate C header file
const gen_header = b.addExecutable(.{
    .name = "gen_header",
    .root_module = b.createModule(.{
        .root_source_file = b.path("scripts/gen_header.zig"),
        .target = target,
        .optimize = optimize,
    }),
});

const run_gen_header = b.addRunArtifact(gen_header);
run_gen_header.addArg("zig-out/include/mufiz.h");

const header_step = b.step("header", "Generate C header file");
header_step.dependOn(&run_gen_header.step);

// Ensure header is generated when building shared library
b.getInstallStep().dependOn(&run_gen_header.step);
```

## Header Contents

The generated header includes:

### Core Library Functions
- `mufiz_init()` - Initialize the library
- `mufiz_deinit()` - Clean up resources
- `mufiz_interpret()` - Execute MufiZ code

### Memory Management
- `mufiz_has_memory_leaks()` - Check for memory leaks
- `mufiz_print_memory_stats()` - Print memory statistics

### String Utilities
- `mufiz_strdup()` - Duplicate a C string
- `mufiz_free_cstring()` - Free a duplicated string

### WASM Compatibility
- `init_wasm()` - Initialize for WebAssembly
- `interpret()` - WASM-friendly interpret function
- `deinit_wasm()` - WASM cleanup

### Package Management
- `mufiz_pm_init()` - Initialize project in current directory
- `mufiz_pm_new()` - Create new project
- `mufiz_pm_info()` - Display project info
- `mufiz_pm_run()` - Run project
- `mufiz_pm_install()` - Install dependencies
- `mufiz_pm_add_dependency()` - Add dependency
- `mufiz_pm_cache_info()` - Display cache statistics
- `mufiz_pm_cache_clear()` - Clear package cache

### Formatting
- `mufiz_format_source()` - Format source code
- `mufiz_format_file()` - Format a file in-place
- `mufiz_needs_formatting()` - Check if formatting needed

## Release Process

During the release process (`scripts/prepare_release_artifacts.sh`):

1. The script ensures the header is generated: `zig build header`
2. The script validates the header matches `c_api.zig`: `zig build validate-header`
3. It copies `zig-out/include/mufiz.h` to the C library package
4. The header is included in the release artifact: `mufiz-c-library-{VERSION}.zip`

If validation fails, the release process stops with an error.

## Important Notes

### DO NOT Manually Edit

❌ **Never manually edit `zig-out/include/mufiz.h`**

The file contains a clear warning:
```c
// This file is AUTO-GENERATED by scripts/gen_header.zig
// DO NOT EDIT THIS FILE MANUALLY
// Source: src/c_api.zig
```

Any manual changes will be lost on the next generation.

### Adding New API Functions

To add new C API functions:

1. Add the `export fn` to `src/c_api.zig`
2. Update `scripts/gen_header.zig` to include the new function signature
3. Regenerate the header: `zig build header`
4. Test that it compiles correctly

### Version Management

The header version is automatically extracted from `build.zig.zon`:

```zig
.version = "0.11.0"
```

This ensures the header version always matches the library version.

## Backward Compatibility

The old manually-maintained header has been backed up to:
- `include/mufiz.h.manual-backup`

This is kept for reference but should not be used. The generated header in `zig-out/include/mufiz.h` is the single source of truth.

## CI/CD Integration

### GitHub Workflows

Both release workflows (`release.yml` and `new_release.yml`) automatically:

1. Build the project (which generates the header)
2. Run `scripts/prepare_release_artifacts.sh` (which validates the header)
3. Package the header with the C library

No manual intervention is needed for releases. If the header doesn't match `c_api.zig`, the CI build will fail.

## Troubleshooting

### Header Not Found During Build

If you see "mufiz.h not found" during the release process:

```bash
# Ensure directory exists
mkdir -p zig-out/include

# Generate header
zig build header

# Verify it was created
ls -l zig-out/include/mufiz.h
```

### Header Out of Sync

If the header seems out of sync with `src/c_api.zig`:

```bash
# Clean and regenerate
rm -f zig-out/include/mufiz.h
zig build header
```

### Compilation Errors in Generator

If `scripts/gen_header.zig` fails to compile:

1. Check Zig version compatibility (requires 0.15.2)
2. Verify `build.zig.zon` format is correct
3. Run `zig build header` to see detailed error messages

## Validation Script

The validation script (`scripts/validate_header.zig`) ensures header completeness:

```zig
// Extracts all export fn declarations from src/c_api.zig
// Extracts all MUFIZ_API declarations from generated header
// Compares the two lists and reports any mismatches
```

**Output Example**:
```
🔍 Validating C header against c_api.zig exports...

Found 21 exported functions in src/c_api.zig:
  - mufiz_init (line 38)
  - mufiz_deinit (line 60)
  ...
```

If any function is missing from the header, the validation fails with exit code 1.
